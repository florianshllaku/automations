Craigslist Outreach Automation

Scrape targeted Craigslist listings → verify with Claude AI → store in Google Sheets → trigger outreach via n8n + Twilio → real-time follow-up via Redis queue after 1 hour of no response.

Proposal Summary

What I will build

End-to-end lead automation — scrape Craigslist, verify with Claude AI, log to Google Sheets for your approval, send SMS + email outreach, and follow up automatically after 1 hour of no response. Self-healing scraper means website changes never break it.

  1. Scrape Craigslist listings matching your criteria
  2. Send full batch to Claude AI — returns PASS or SKIP per listing
  3. PASS listings written to Google Sheets as new rows
  4. You set Status to "Send Message" to approve outreach
  5. n8n sends personalized SMS + email via Twilio
  6. Redis + Bull queues a follow-up job — fires at exactly 1 hour if no reply
  7. Twilio reply webhook + Gmail poller update the sheet in real-time
  8. If the website changes, the scraper detects the broken selector, asks Claude to find the new one, and updates itself automatically

Self-Healing Scraper (Built-in)

How it works — requests + BeautifulSoup

Craigslist is server-rendered — no browser needed. CSS selectors live in selectors.json alongside a plain-English intent. If a selector breaks, the scraper sends the raw HTML to Claude, gets a corrected selector back, updates the JSON, and retries. Zero manual intervention.

This is the direct answer to: "How do you handle website changes?"

The scraper heals itself. No downtime, no manual fixes, no monitoring required.

AI Analysis — How It Works

The approach — one Claude call, full batch

The scraper collects all listings and builds a CSV in memory. The entire CSV is sent to Claude in a single API call along with the criteria from config.json. Claude adds a verdict column to each row — PASS or SKIP. One call, all rows decided at once. The output is the same CSV back with the verdict column added.

Step 4 — Filter PASS rows → append to Google Sheets

SKIP rows are dropped. Only PASS rows are sent to the Google Sheets API as new rows appended to the bottom of the existing sheet. No overwrite — existing data is never touched.

Note on batch size

Claude's context window handles hundreds of rows comfortably. For very large scrapes (>100 rows), the CSV is split into chunks of 50 and sent in separate calls — results are merged before writing to the sheet.

n8n Workflow A — Initial Outreach

1
Webhook Trigger Google Apps Script fires POST with row payload: name, phone, email, title, URL, row index. Triggered when Status dropdown is set to "Send Message".
2
Build Personalized Message n8n composes message using listing title and name. Template is configurable. Example: "Hi [Name], I saw your listing for [Title]..."
3
Route: SMS or Email or Both If phone exists → Twilio SMS. If email exists → Gmail via SMTP / SendGrid. If both → send both channels.
4
Write Timestamp Back to Sheet n8n writes "Contacted At" timestamp to column J and updates Status to "Contacted". Workflow ends here — no waiting, no pausing.

Reply Detection

SMS Reply — Twilio Webhook

Contact replies to SMS → Twilio fires a POST to n8n Workflow B in real-time → updates Response Received = Yes in the sheet. No polling.

Email Reply — Gmail Apps Script Poller

Gmail doesn't push events. Apps Script runs every 15 min, checks inbox for replies, matches to sheet rows by email, writes Response Received = Yes. Free, no external service needed.

1-Hour Follow-up — How It Works

Redis + Bull Queue — real-time, per contact

Workflow A enqueues a delayed job in Redis (delay: 1hr) per contact. Bull fires Workflow C at exactly 1hr — accurate to the second. No polling, no Wait node, no limits.

1
Workflow A ends — enqueue delayed job n8n POSTs { rowId, contact, delay: 3600 } to Bull. Job stored in Redis. Workflow A closes immediately — nothing held open.
2
Redis holds the job for exactly 1 hour Each contact = its own independent job. 10 contacts = 10 timers running in parallel, each firing at their own exact time.
3
1 hour passes — Bull fires the job Checks Response Received for that row. Empty → calls n8n Workflow C. Already replied → job discarded.
4
n8n Workflow C sends follow-up Sends follow-up via SMS or email. Updates sheet Status → Follow-up Sent. 1 follow-up per contact, no more.
5
Job removed from queue Bull removes the completed job from Redis. No leftover state. Queue stays clean.
Why Redis + Bull

Fires at exactly 1hr per contact. Scales to any volume. Built-in retry on failure. Jobs persist through server reboots — no lost follow-ups.
